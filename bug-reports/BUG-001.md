# [BUG-001] [Login] Password Input Displayed in Plaintext Without Character Masking

## Environment
- **Build**: Jetpack Compose & React Native (Broken build)
- **Device/OS**: Android 14 (API 34) on Pixel 7 Emulator
- **Detected By**: Espresso (`LoginTest.kt`) & Appium (`test_login.py`)
- **Target Element**: `login-password`

## Steps to Reproduce
1. Launch app with fresh state on the Login screen.
2. Focus the Password input field (`login-password`).
3. Enter `password123`.
4. Inspect the rendered characters and element attributes.

## Expected Result
Password characters must be masked with bullet/dot symbols (`PasswordVisualTransformation` in Compose / `secureTextEntry={true}` in React Native). The accessibility node must expose `password="true"` and `SemanticsProperties.Password`.

## Actual Result
Entered password characters are displayed completely in plaintext. The accessibility attribute reports `password="false"`, exposing user credentials.

## Severity & Impact
- **Severity**: Critical
- **Rationale**: Direct security vulnerability exposing sensitive user authentication credentials in cleartext on screen and through screen readers.

## Scope & Blockers
- **Cross-Build Behavior**: Reproduces on both Jetpack Compose (`MainActivity.kt`) and React Native (`LoginScreen.js`).
- **Blocks**: None (non-blocking for downstream navigation).
