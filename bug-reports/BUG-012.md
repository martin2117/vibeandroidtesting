# [BUG-012] [Checkout] Empty Checkout Form Submission Bypasses Required Field Validation

## Environment
- **Build**: Jetpack Compose & React Native (Broken build)
- **Device/OS**: Android 14 (API 34) on Pixel 7 Emulator
- **Detected By**: Maestro, Appium, Espresso, UI Automator (Verified on fixed proceed hook)
- **Target Element**: `checkout-submit`, `checkout-error`

## Steps to Reproduce
1. Launch app with clean state and log in (`demo@techshop.com` / `password123`).
2. Add Product 1 (`add-p1`), switch to Cart (`tab-cart`), and navigate to Checkout (`proceed-checkout`). *(Note: On broken build, reaching Checkout requires patching blocker `BUG-011` / setting `Screen.Checkout`)*.
3. Leave all customer and payment fields blank (`checkout-firstName`, `checkout-lastName`, `checkout-email`, `checkout-phone`, `checkout-card`, `checkout-expiry`, `checkout-cvv`).
4. Tap the "Place Order" button (`checkout-submit`).

## Expected Result
Form submission must be rejected. The app must stay on the Checkout screen, display an error banner (`checkout-error`) indicating required fields are missing, and block order generation.

## Actual Result
The form submits immediately with blank fields, creates an order with empty customer data, and transitions to the Confirmation screen.

## Severity & Impact
- **Severity**: Major
- **Rationale**: Corrupts order databases with empty customer identities, shipping details, and unverified payments.

## Scope & Blockers
- **Cross-Build Behavior**: Reproduces on both Jetpack Compose (`MainActivity.kt`) and React Native (`CheckoutScreen.js`).
- **Blocks**: Gated behind `BUG-011` on the broken build.
