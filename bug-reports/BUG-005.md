# [BUG-005] [Cart] Quantity Stepper Allows Decrementing Below 1 to Zero and Negative Values

## Environment
- **Build**: Jetpack Compose & React Native (Broken build)
- **Device/OS**: Android 14 (API 34) on Pixel 7 Emulator
- **Detected By**: Maestro, Appium, Espresso, UI Automator
- **Target Element**: `qty-dec-p1`, `qty-p1`

## Steps to Reproduce
1. Launch app and log in (`demo@techshop.com` / `password123`).
2. Add Product 1 to the cart (`add-p1`).
3. Navigate to Cart screen (`tab-cart`) (Product 1 quantity is `1`).
4. Tap the decrement button `−` (`qty-dec-p1`).

## Expected Result
Quantity stepper must enforce a minimum boundary of `1` (or prompt for item removal via the dedicated "Remove" button). Decrementing below 1 must be disallowed.

## Actual Result
Quantity decrements to `0`, `-1`, `-2`, etc. without boundary validation, resulting in negative line items and invalid cart totals.

## Severity & Impact
- **Severity**: Major
- **Rationale**: Corrupts cart state and pricing totals with zero and negative item quantities.

## Scope & Blockers
- **Cross-Build Behavior**: Reproduces on both Jetpack Compose (`AppViewModel.kt`) and React Native (`CartContext.js`).
- **Blocks**: None.
