# [BUG-006] [Cart] Displayed Order Total Fails to Update Dynamically Due to Unkeyed State Memory

## Environment
- **Build**: Jetpack Compose & React Native (Broken build)
- **Device/OS**: Android 14 (API 34) on Pixel 7 Emulator
- **Detected By**: Maestro, Appium, Espresso, UI Automator
- **Target Element**: `order-total`, `qty-inc-p1`, `remove-p1`, `apply-discount`

## Steps to Reproduce
1. Launch app and log in (`demo@techshop.com` / `password123`).
2. Add Product 1 ($60.00) to the cart and open Cart screen (`tab-cart`).
3. Observe initial order total: "Total: $60.00".
4. Tap increment `+` button (`qty-inc-p1`) to change quantity from 1 to 2 (Subtotal: $120.00).

## Expected Result
Order total text must reactively recompute and display the updated sum: "Total: $120.00".

## Actual Result
The displayed total remains frozen at the initial cached value "Total: $60.00" because Compose uses an unkeyed `remember { vm.total }` (and RN uses an un-updated effect), failing to trigger UI re-composition when cart state changes.

## Severity & Impact
- **Severity**: Critical
- **Rationale**: Core shopping cart breakdown — customers cannot see accurate item costs or final totals as they adjust cart contents.

## Scope & Blockers
- **Cross-Build Behavior**: Reproduces on both Jetpack Compose (`MainActivity.kt`) and React Native (`CartScreen.js`).
- **Blocks**: None.
