# [BUG-013] [Checkout] Order Confirmation Screen Omits Generated Order Reference Number

## Environment
- **Build**: Jetpack Compose & React Native (Broken build)
- **Device/OS**: Android 14 (API 34) on Pixel 7 Emulator
- **Detected By**: Maestro, Appium, Espresso, UI Automator (Verified on fixed proceed hook)
- **Target Element**: `confirmation-title`, Order reference text

## Steps to Reproduce
1. Launch app with clean state and log in (`demo@techshop.com` / `password123`).
2. Add Product 1 (`add-p1`), switch to Cart (`tab-cart`), and navigate to Checkout (`proceed-checkout`). *(Note: On broken build, reaching Checkout requires patching blocker `BUG-011` / setting `Screen.Checkout`)*.
3. Fill valid checkout fields:
   - First Name: `Jane`, Last Name: `Doe`
   - Email: `jane.doe@example.com`, Phone: `5551234567`
   - Card Number: `4111222233334444`, Expiry: `12/28`, CVV: `123`
4. Tap "Place Order" (`checkout-submit`).
5. Observe the Confirmation screen UI.

## Expected Result
Confirmation screen must display the confirmation title (`confirmation-title`), items purchased, total amount, and prominently render the generated order reference ID (`TS-XXXXXX`).

## Actual Result
The generated order reference parameter (`orderRef`) is omitted from the UI rendering. The screen displays only generic text "Thank you for your order" with no reference ID visible.

## Severity & Impact
- **Severity**: Major
- **Rationale**: Prevents customers and support staff from tracking, auditing, or servicing completed purchases.

## Scope & Blockers
- **Cross-Build Behavior**: Reproduces on both Jetpack Compose (`MainActivity.kt`) and React Native (`ConfirmationScreen.js`).
- **Blocks**: Gated behind `BUG-011` on the broken build.

## Evidence
- Blocked by `BUG-011` in [`maestro/maestro-report.xml`](file:///Users/mac/vibeandroidtesting/maestro/maestro-report.xml) and [`appium/appium-report.xml`](file:///Users/mac/vibeandroidtesting/appium/appium-report.xml)
